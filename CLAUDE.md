# CLAUDE.md

Guidance for working in this repo. Keep it current when structure or conventions change.

## What this is

Terraform for the **Playterry** production environment on Azure. Single root module
that composes seven local modules under `modules/`. There is no live state or CI
here yet — it is a greenfield scaffold. `README.md` has the architecture narrative;
this file is about *working on the code*.

## Tooling

- **Terraform >= 1.6**, provider **hashicorp/azurerm ~> 4.0**, **hashicorp/random ~> 3.6**.
- `terraform` is **not installed** on the authoring machine. Anything that needs it
  (`fmt`, `validate`, `plan`) must be run by the user. Always end a change by telling
  them to run:
  ```
  terraform fmt -recursive && terraform validate
  ```
- State backend is `azurerm`, defined but commented out in `backend.tf`.

## Layout

```
main.tf          root wiring: resource group, Log Analytics, all module blocks
variables.tf     every input; module-specific inputs are grouped with comment banners
outputs.tf       flattened outputs pulled from module outputs
providers.tf     azurerm provider + features{}
versions.tf      required_version / required_providers
backend.tf       commented azurerm backend
modules/
  network/               VNet, 7 subnets, NSGs, SQL-MI route table + associations
  vpn-p2s/               Virtual Network Gateway, P2S OpenVPN + Entra ID auth
  aks/                   reusable private AKS cluster (instantiated twice)
  loadbalancer/          Standard Azure LB (instantiated per cluster)
  sql-managed-instance/  SQL MI + azurerm_mssql_managed_database (for_each)
  redis/                 Azure Cache for Redis + private endpoint + private DNS zone
  iis/                   2x Windows/IIS VMs + availability set + CustomScriptExtension
  application-gateway/   App Gateway v2 (WAF) in front of the IIS pool
```

## Conventions

- **Naming**: every resource name is `"${var.name_prefix}-<role>..."` where the root
  passes `name_prefix = "${var.brand}-${var.environment}"` (→ `playterry-prod`).
  Modules never build the prefix themselves — they receive it.
- **Tags**: root builds `local.base_tags` and passes `tags` to every module and
  resource. Modules always accept a `tags` variable (default `{}`).
- **Module I/O**: each module is `main.tf` + `variables.tf` + `outputs.tf`. Modules
  take already-resolved IDs (subnet IDs, workspace ID) from the root — they do not
  look resources up with data sources.
- **Grouped object variables**: tunables are bundled into one object variable per
  concern (`aks_defaults`, `sql_managed_instance`, `redis`, `iis`,
  `application_gateway`, `load_balancer`) using `optional(...)` with defaults, so
  `terraform.tfvars` stays small. `sql_databases` is a `map(object)` keyed by
  database name.
- **Secrets**: `sql` / `iis` admin passwords are generated by `random_password` in
  root `main.tf` when the caller leaves them unset, then surfaced as `sensitive`
  outputs. Never echo these in plan output or logs.
- **azurerm 4.x attribute names** — this codebase uses the v4 spellings:
  `auto_scaling_enabled` (not `enable_auto_scaling`), `bgp_route_propagation_enabled`
  (not `disable_bgp_route_propagation`), `role_based_access_control_enabled`,
  `non_ssl_port_enabled` on `azurerm_redis_cache` (not `enable_non_ssl_port`), etc.
  When adding resources, verify against the v4 provider docs, not v3.

## Things that will bite you

- **`modules/network` must apply before `modules/sql-managed-instance`.** The MI
  needs the subnet delegation + route-table association + NSG rules in place;
  `module.sql` has an explicit `depends_on = [module.network]`. Keep it.
- **`GatewaySubnet`** is a literal Azure-reserved name — don't rename it.
- **`modules/redis` also has `depends_on = [module.network]`** — it needs
  `snet-redis` + its NSG for the private endpoint. The module owns the
  `privatelink.redis.cache.windows.net` private DNS zone and the VNet link;
  don't add a second copy of that zone elsewhere. Redis is private-endpoint
  only (`public_network_access_enabled = false`).
- **First apply takes hours** (SQL MI + VPN gateway). Don't assume a hang.
- **AKS clusters are private** (`private_cluster_enabled = true` default). Plans/tests
  that talk to the K8s API only work from inside the VNet / over the VPN.
- **App Gateway listener is HTTP:80 only.** Adding TLS means a new `frontend_port`,
  `http_listener`, and a Key Vault `ssl_certificate` — in the module, not the root.
- Both AKS clusters intentionally share the non-routed service/pod CIDRs.
- Removing a key from `sql_databases` **drops that database** on next apply.
- `README.md` has a **Cost estimate** table tied to the default SKUs/sizes
  (SQL MI 4 vCore, AKS D4s/D8s pools, Redis Standard C3, App Gateway WAF_v2,
  IIS D2s_v5). If you change a sizing default, re-check that table.
